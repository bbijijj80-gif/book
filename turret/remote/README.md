# Выносной пульт: ESP32 + дисплей Nextion

Физический пульт управления турелью вместо (или в дополнение к) браузеру.

```
[ Экран Nextion ] --UART(9600, 3.3V)--> [ ESP32 ] --Wi-Fi--> [ Raspberry Pi 4 ]
   касания кнопок                        мост              REST API turret
```

ESP32 ничего не решает "по-крупному" сам — это просто мост: читает касания
кнопок с экрана и дёргает тот же самый REST API (`/api/arm`, `/api/mode`,
`/api/manual_move`, `/api/fire`, `/api/center`, `/api/emergency_stop`,
`/api/status`), которым уже пользуется браузерный веб-интерфейс. Вся
безопасность (старт всегда DISARMED, лимиты очереди выстрелов, водопад
`max_continuous_fire_seconds` и т.д.) по-прежнему обеспечивается кодом на
Pi — так же, как и раньше, независимо от того, через что пришла команда.

**На Raspberry Pi менять ничего не нужно.** Он уже отдаёт этот API по Wi-Fi
на весь адрес `http://<IP-Pi>:8080` — тот же самый, которым вы открываете
страницу в браузере. ESP32 просто становится ещё одним клиентом в той же
локальной сети.

## Что понадобится

| Компонент | Примечание |
|---|---|
| Плата ESP32 (любая с Wi-Fi, напр. ESP32-WROOM-32 DevKit) | |
| Дисплей Nextion NX1060P101-011C-1 | 10.1", предположительно 1024×600 — уточните по наклейке |
| MicroSD-карта | только для однократной загрузки прошивки экрана |
| Отдельный источник 5V (для экрана) | см. про питание ниже |
| USB-кабель для ESP32 | питание + загрузка прошивки |

## Подключение

| Nextion | ESP32 | Комментарий |
|---|---|---|
| 5V | — (отдельный БП) | НЕ от ESP32 — см. ниже |
| GND | GND | Обязательно общий с ESP32 |
| TX | GPIO16 (RX2) | |
| RX | GPIO17 (TX2) | Перекрёстно: TX экрана → RX платы, и наоборот |

**Про питание экрана:** 10.1" панель с подсветкой может потреблять до
несколько сотен мА — больше, чем безопасно брать с регулятора на плате
ESP32. Запитайте Nextion от отдельного стабильного 5V (тот же блок питания,
что и остальная электроника турели, или отдельный USB-адаптер) — но **землю
(GND) обязательно соедините** между Nextion и ESP32, иначе UART работать не
будет (или будет нестабильно).

**Про уровни сигналов:** логические пины UART у Nextion — 3.3V (как и у
ESP32), напрямую совместимы без резисторных делителей/преобразователей
уровня. Если сомневаетесь — сверьтесь с даташитом именно вашей модели,
я не смог проверить это для конкретно `NX1060P101-011C-1`.

Если ваша плата ESP32 — вариант с PSRAM (WROVER) и GPIO16/17 у неё заняты
под память, в скетче замените `NEXTION_RX_PIN`/`NEXTION_TX_PIN` на другую
свободную пару, например 25 и 26.

## Настройка Arduino IDE

1. **Установите поддержку ESP32** (если ещё нет): `Файл → Настройки →
   Дополнительные ссылки для менеджера плат`, добавьте:
   ```
   https://raw.githubusercontent.com/espressif/arduino-esp32/gh-pages/package_esp32_index.json
   ```
   Затем `Инструменты → Плата → Менеджер плат`, найдите `esp32` (автор
   Espressif Systems), установите.
2. **Выберите плату**: `Инструменты → Плата → ESP32 Arduino → ESP32 Dev Module`
   (или конкретную модель, если она есть в списке).
3. **Поставьте библиотеку**: `Инструменты → Управление библиотеками`, найдите
   `ArduinoJson` (автор **Benoit Blanchon**) — важно поставить именно
   **версию 7.x**, скетч написан под её API.
4. Откройте `esp32_nextion_remote/esp32_nextion_remote.ino` из этой папки.

## Настройка и загрузка прошивки

В начале файла `esp32_nextion_remote.ino` замените:
```cpp
const char* WIFI_SSID     = "ВАШ_WIFI";
const char* WIFI_PASSWORD = "ВАШ_ПАРОЛЬ";
const char* PI_BASE_URL   = "http://192.168.1.50:8080";  // реальный IP вашего Pi
```
IP-адрес Pi узнать можно прямо на нём: `hostname -I`.

Подключите ESP32 по USB, выберите порт (`Инструменты → Порт`), нажмите
"Загрузить" (стрелка). После загрузки откройте `Инструменты → Монитор
порта` на скорости **115200** — там видно, подключился ли Wi-Fi и что
происходит при каждом нажатии кнопок (полезно для отладки).

## Экран Nextion

Экран программируется отдельно, через фирменный Nextion Editor (не из
Arduino IDE) — точная пошаговая спецификация, что и как собрать на
странице, в [`docs/nextion-ui-spec.md`](docs/nextion-ui-spec.md).

## Порядок первого включения

1. Соберите проводку (см. таблицу выше), пока ESP32 **не подключайте к
   Pi/сети** — сначала проверьте, что экран вообще откликается.
2. Прошейте экран через SD-карту (см. спецификацию).
3. Загрузите прошивку в ESP32, откройте монитор порта.
4. Подайте питание на всё разом. В мониторе порта должно появиться
   "Wi-Fi подключён, IP: ...", а на экране в поле связи — `OK`.
5. Нажмите MODE, UP/DOWN/LEFT/RIGHT, CENTER — проверьте в мониторе порта,
   что каждое нажатие логируется (`POST /api/... -> 200`), и что турель
   реагирует (или хотя бы веб-интерфейс в браузере показывает смену режима).
6. Только когда всё остальное проверено — пробуйте ARM. Помните: первое
   нажатие только запрашивает подтверждение (`CONFIRM?` на экране), второе
   в течение 3 секунд — взводит по-настоящему.

## Если что-то не работает

- **Экран ничего не показывает после включения** — проверьте питание
  отдельно от ESP32 сначала; если есть подсветка, но нет реакции на
  касания — проверьте, что TFT-файл реально загрузился (была ли просьба
  подтвердить прошивку при вставке SD-карты).
- **В мониторе порта не видно "Wi-Fi подключён"** — неверные SSID/пароль,
  или Wi-Fi роутера ESP32 не видит (2.4ГГц? ESP32 не умеет 5ГГц Wi-Fi).
- **"NET PI" на экране постоянно** — проверьте `PI_BASE_URL` (правильный ли
  IP, не сменился ли у Pi), и что `python main.py` на Pi реально запущен.
- **Кнопки не реагируют, монитор порта молчит при нажатии** — скорее всего
  забыли включить "Send Component ID" в Touch Press/Release Event для
  кнопки в Nextion Editor (см. спецификацию), либо перепутаны TX/RX между
  платами (они должны быть перекрёстно).
- **Ошибка компиляции в Arduino IDE** — пришлите текст ошибки целиком,
  этот скетч не компилировался в песочнице (нет доступа к серверам
  Arduino/Espressif оттуда), поэтому теоретически возможны опечатки,
  которые ловит только настоящий компилятор.
